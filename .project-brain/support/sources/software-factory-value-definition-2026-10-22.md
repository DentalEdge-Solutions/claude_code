# Software Factory — Value Definition & Strategic Direction

## Objective

Our goal is to evolve `claude_code` into a highly capable, reliable, efficient, and progressively self-improving Software Factory that can deliver production-ready applications with minimal routine human intervention.

**Value means measurable improvements in software quality, autonomous execution, delivery efficiency, security, maintainability, and intelligent reuse of existing solutions.**

## Evaluation Priorities

Assess the reference projects against these priorities:

1. **Engineering Quality (30%):** Correctness, testing, independent verification, fewer defects, and reduced rework.
2. **Autonomy & Orchestration (20%):** Effective agent coordination, parallel execution, workflow automation, recovery, and minimal human intervention.
3. **Development Productivity (15%):** Faster delivery, shorter feedback loops, and reduced engineering effort.
4. **Security & Reliability (15%):** Safe execution, isolation, permissions, resilience, observability, and appropriate approval gates.
5. **Maintainability & Adaptability (10%):** Architectural simplicity, modularity, reusable capabilities, and controlled continuous improvement.
6. **Resource Efficiency (10%):** Optimized token consumption, model utilization, infrastructure costs, and operational overhead.

Treat these weights as strategic guidance, not rigid scoring rules. Security and correctness are mandatory acceptance criteria.

## Reference-Driven Engineering & Intelligent Reuse

A fundamental objective is enabling our Software Factory to intelligently leverage existing projects, architectures, skills, agents, and implementations rather than unnecessarily reinventing solutions.

For every valuable capability identified, determine the best approach:

- **REUSE:** Adopt an existing compatible component.
- **ADAPT:** Modify an existing implementation.
- **COMPOSE:** Combine complementary capabilities.
- **REIMPLEMENT:** Recreate proven functionality using a more appropriate architecture.
- **BUILD NEW:** Develop functionality when existing solutions are inadequate.
- **REFERENCE ONLY / REJECT:** Preserve useful knowledge or exclude unsuitable approaches.

Evaluate these decisions based on technical suitability, verified functionality, licensing, security, compatibility, implementation effort, integration risk, and long-term maintenance.

**This decision-making capability should also become part of our Software Factory's standard approach when developing future applications from supplied reference projects.**

## Measurement Criteria

Where feasible, establish baselines and assess improvements using:

- First-pass acceptance rate and defect/rework frequency.
- Time from specification to verified delivery.
- Human interventions per successfully completed task.
- Successful autonomous execution and failure recovery.
- Cost and token consumption per accepted deliverable.
- Integration complexity and long-term maintenance burden.
- Effectiveness of reuse versus adaptation or new development.

Distinguish demonstrated results from estimates, architectural potential, and unverified claims.

## Strategic Direction

Our existing `claude_code` project already includes substantial research, reference-repository, skill/agent adaptation, evaluation, and software-delivery capabilities.

**Prioritize strengthening and connecting these existing capabilities rather than introducing redundant systems.**

Identify what already works, what needs improvement, what is missing, and which external approaches offer demonstrable advantages.

Favor native functionality, selective integration, proven engineering patterns, architectural coherence, and measurable long-term value.

Preserve existing security controls, source provenance, independent verification, and human approval for consequential changes.

Do not assume that more agents, more automation, or greater architectural complexity necessarily create value.

## Research Autonomy

You have full discretion to determine the research methodology, evaluation depth, delegation strategy, comparative framework, and presentation of findings.

Use your judgment to prioritize the most consequential discoveries and avoid unnecessary analysis.

Support important conclusions with evidence and clearly distinguish implemented capabilities from documented claims.

**Do not implement changes during this research.** Produce an evidence-backed optimization strategy and prioritized recommendations for approval.

## Ultimate Success Criterion

The Software Factory should not merely write code faster.

It should **intelligently determine the best way to build software, leverage existing solutions whenever appropriate, execute development workflows reliably, and deliver independently verified results with minimal unnecessary human effort and architectural complexity.**

Use this definition of value to guide all repository evaluations, architectural comparisons, and optimization recommendations.
