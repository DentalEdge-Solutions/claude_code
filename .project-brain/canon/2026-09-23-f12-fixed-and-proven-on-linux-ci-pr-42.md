F12 landed on main via PR #42 (merge 8f7b61a), CI green ON THE MERGE COMMIT (run 35891303120): layout-integration executed 30, skipped 0 — 22 before F12, so all eight new Tier 2 tests ran with REAL uids and gids; bind-agreement executed 6, skipped 0; hermes bin 31/31. WHAT IT FIXES: approvals were impossible — approve-changeset.py runs as root and left the lock sidecar root-owned 0600, so reserve_approval as hermes-broker failed on the FIRST apply and no change-set could ever be approved; and run records were written into the gateway-owned vault (data/ 700 uid 10000, not in ReadWritePaths). Run records now go to <store>/records/<slug>/ (files 0640, per-client dir 0o2750); approval 0640, snapshot 0640, sidecar 0660, owner hermes-broker:hermes when root, all set fd-based BEFORE the rename; approve-changeset.py refuses non-root on Linux. The executor could not have written the vault either (ads-mutator has no vault mount; adding one would widen F9's pinned bind set), so moving the records was the only fix that leaves the security gate alone — proxy, allow-list, seven binds, both units and docker-compose.yml are absent from the diff. TWO SPEC BUGS FOUND BY TRACING, BEFORE CI: R1 — 0750 on the per-client dir strips the S_ISGID inherited from setgid records/, so files would land hermes-broker:hermes-broker and group hermes could not read them (darwin hides this; BSD vs System V); R2 — fixing the sidecar was necessary but NOT sufficient, because approvals/<slug>/ created by a bare os.makedirs as root lands 02755 and the broker still could not create its .tmp file there — F12's symptom one file over. LESSONS EARNED: (1) a new exception type (RuntimeError from _apply_owner_mode) escaped BOTH callers — invisible to every task-scoped review because it lived in the gap between two tasks that each looked correct alone; in hermes-broker.py an escape on the record_outcome path runs AFTER the executor and would skip _write_result, turning a missing result into a wrong one, and the broker carried a comment enumerating the exceptions those functions raise that this branch silently falsified. Only the whole-branch review could see it. (2) CI caught 13 approve-changeset tests that on Linux never reached the logic they claimed to test — the new root guard bounced them at exit 2 while darwin passed 46/46 and hid it; the fix neutralises the guard in the fixture (frame-scoped, so changeset_lib's own root check is not fooled) rather than skipping on Linux, which would have preserved the hole. (3) A findings record claimed 'Tier 2 on Linux CI reproduces...' when no CI run existed; it was staged as design-intent with a placeholder and filled only after the run produced a number.
