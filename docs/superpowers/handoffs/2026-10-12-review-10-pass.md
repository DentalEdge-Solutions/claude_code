## What this round taught about running a review

1. **A number that differs from the runbook's expected text is a stop, even when it looks harmless.** The
   first trial showed `(4 places)` where the runbook said 3. The cause was the summary tool counting a key
   named `could-not-check` in D4.5's history (a count of past runs) as a field that was not read. Fixed in
   PR #115, with a note in the runbook.
2. **Every value a paste-safe tool prints goes through its print rule.** The fix above first printed the run
   count raw, past the tool's 15-digit number rule; the automatic review of the commit caught it.
3. **Read an expiry before saying a step is needed.** The agent said review #10 needed a new chat audit
   "either way"; the result of 2026-10-09 was valid until 2026-10-16. A real audit costs money.
4. **The full `--last-pass-execstart` value is in no public file.** Take it from the last PASS's private box
   bundle: on the laptop, `python3 tools/last_pass_hash.py <that bundle> | pbcopy` (it prints nothing else),
   paste it on the box at a `read -r H` prompt, clear with `pbcopy < /dev/null`. For review #11 the bundle is
   `review-10/bundle-box.json`.
5. **A finding in the evidence file is `accepted (reason)`, `fixed` or `blocking`.** "Open; decided" is none
   of them: the reviewer cannot pass D9.1 on it. An acceptance says for which review and why.
6. **A shell redirect on the box creates the bundle with the login's default mode** (`664` here). `umask 077`
   first, until the collector writes the file itself.
7. **The sign-off carries the bundles' UTC day.** Start a review early enough in the UTC day to finish it;
   after midnight UTC both bundles are collected again.
8. **Before signing, check the report against the checklist yourself:** the same items in the same order,
   the closest pass rules read again, and a scan for 64-character hex values, e-mail addresses and
   addresses. `0.0.0.0` is the only non-loopback address the report may show.
9. **Record only what was measured.** A draft of the rollout's record gave the pull "about 15:00 UTC" with
   no reading behind it; it now says "before the first trial collection".
10. **In the summary tool's tests the starting bundle already has one `could-not-check` item** (D5.3): a test
    of "nothing is could-not-check" must remove it first, or it proves nothing.
