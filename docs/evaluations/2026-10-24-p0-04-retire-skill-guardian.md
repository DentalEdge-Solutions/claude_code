## What was removed and why

| Removed (`git rm`) | What it was |
|---|---|
| `.claude/agents/skill-guardian.md` | An orchestrator agent that ran its own context refresh, AgentShield scan, eval and refine loop |
| `PROJECT-SKILL-HEALTH.md` (repo root) | Its report, dated 2026-06-23 |
| `evals/agents/skill-guardian/evals.json` | Its agent-eval scenario spec, the only tracked file in that folder |

Two reasons, both from the strategy record:

- **Unused.** Telemetry for July to October counts 0 invocations of skill-guardian (S2 §1, 1,199 invocation events in
  total).
- **A write-capable reader of untrusted text.** Its tools were `Read, Write, Edit, Bash, Glob, Grep, WebSearch,
  WebFetch` (frontmatter at `fabaad9`). It could read arbitrary web pages and write, edit and run commands in the
  same context (breach (b), S3 §2.4: target "retired").

Its function is covered by `skill-eval-agent` / `agent-eval` and `skill-refine-agent` / `agent-refine`. These use the
evaluation method from E12 and the evaluator pin from P0-11. skill-guardian ran a second, weaker method: no harvest,
no manifest, no no-skill baseline and a 3-iteration cap (S2 OPP-30).

## Acceptance

**Test first.** `scripts/retired-skill-guardian.test.js` was committed red (`827356d`), with 58 stale references. It
is discovered by `run-all-tests.js` because its name ends in `.test.js` under `scripts/`.

How the test works:

- It reads `git ls-files`. Without git (a source export), it walks the tree instead.
- It fails if any tracked file names `skill-guardian` or `PROJECT-SKILL-HEALTH` (case-insensitive), outside these
  exclusions:
  - `.project-brain/canon/` (DECISION-S3-5);
  - `docs/evaluations/` and `docs/superpowers/` (dated records);
  - the Hermes runtime data folder (never read; nothing tracked there);
  - basenames ending `-EVAL.md` or `-REFINE-LOG.md` (dated run reports);
  - the test file itself.
- One line is allowed, not a file: the README cleanup line. It must name the file to delete, so it cannot avoid the
  name. The whole line is stored and must be equal, and it must appear exactly once, so the allowance cannot widen or
  go stale silently. The allowance was added in `22f9a6f`, after the red commit, when the cleanup line was written
  (disclosed in that commit message). Round 1 (PR4-R-1) found that the first version was a substring match: a second
  reference appended to the line still passed. The fix is red at `f231516` and green at `21ddfcc`. A test case proves
  that text appended or prepended to the line, or the same line in another file, is a hit. Measured: with
  " Or run skill-guardian." appended to the README line, the acceptance test fails.
- A further check fails if the exclusions would cover README, the USER-GUIDE, `install.sh`, `CLAUDE.md`, a live agent
  or `evals/.gitignore`.

## Targets and deploy

- **Targets that already have it.** `uninstall.sh` discovers agents from this repo (`find .claude/agents`, `:56`), so
  it cannot remove a `skill-guardian.md` that an earlier install copied into a target. README's Removal section tells

  `CLAUDE.md` keeps the old health-check line. Running `uninstall.sh` and then `install.sh` refreshes it (README says
  so).

  after merge (`cp -R skills/project-audit/. ~/.claude/skills/project-audit/`). The owner then runs
