## Not on the checklist

1. **Revocation is not surgical for the write credential, and the README says it is.** README (credential table, "What is NOT lost") claims revocation stays surgical because Hermes has its own OAuth client. Canon credential-governance rule 1, amended 2026-08-19 from a measured outage, says the opposite: a separate OAuth client gives no revocation isolation, and the boundary is the account. The laptop bundle also shows both roles on one client (`client_id_sha12 10af87554726` for both rows). The read role is safe because it is a different account. But revoking the Hermes write grant can take down the operator's other grants on the same human ADMIN account, and the reverse is also true. *Recommendation:* correct the README to match canon. Weigh this in D3.2 (a dedicated STANDARD account removes the problem), and state the expected collateral in the D8.2 procedure. Not blocking on its own, but it bears directly on D3.2 and D8.2.
2. **Gateway secrets outside the authorised-set scope.** The sweep lists `/opt/projects/claude_code/infra/hermes-agent/.env` as `kind: candidate`, `root:root 0600`, size 2387. The findings doc says the box's `.env` holds the Anthropic/provider key and the dashboard basic-auth password, and that the gateway loads it via `env_file`. F19 shows those values were once readable through the proxy. D2 counts only Google Ads credentials, so nothing in this review states what this file holds or whether the Anthropic key is still the bring-up dummy or now real. *Recommendation:* the operator states the variable names (not values) in this file and whether each is real. Consider adding a "non-Ads secrets" line to the authorised set in checklist v1.4. Not blocking; the mode is correct.
3. **Checklist defects to fix in v1.4.** D1.6's expected value (`empty`) contradicts the documented design (the proxy account must be in `docker`). D2.1 should say how the standard `-xdev` exclusions are pre-explained, so every review does not fail on them. Neither issue is a box problem. *Recommendation:* amend the checklist. Note that doing so changes the fingerprint's `checklist` component, which forces a re-review.
