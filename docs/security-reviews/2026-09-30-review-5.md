## Not on the checklist

This reviewer did not read earlier reviews, so some of these may already have been raised. The operator can skip any that are already decided.

1. **The expectation was relaxed during this review's own collection.** v1.9 required `audit_logs.rows` mode `0o700`. The box showed `0o711`, and v1.10 (PR #82) changed the expectation to match the box before the bundle was re-collected. The stated reason is consistent and narrow: traverse-only, no listing, so uid 10000 can reach one handed-over file. Changing a checklist to fit an observation in the middle of a review is still a pattern to watch. **Recommendation:** keep a rule that any relaxation of an expected value is stated in the operator's evidence together with the design reference (as was done here), and is never made silently.
2. **File modes inside `audit_logs/<client>/` are not collected.** Each row is `root 0o711`: anyone can traverse it but nobody except root can list it. uid 10000 "may traverse it to reach the one handed-over `snapshot.stdout`". The owner is root and the group is not reported, so uid 10000 most likely reads that file through the *other* permission bits. If so, every local account (`hermesops`, `hermes-broker`, `hermes-docker-proxy`) can read it too, because the name is fixed and predictable, and client-directory names are guessable slugs. The step logs beside it could be world-readable in the same way, and D7.1 would not see it. **Recommendation:** have the collector report owner, group and mode for each file in each `audit_logs` row (counts only, no names). Require step logs to be `0600 root`. Grant `snapshot.stdout` to uid 10000 by group or ACL rather than `o+r`, or state that `o+r` is accepted.
3. **The expected value of `memory_sweep.unreadable` does not match practice.** The checklist expects it empty. The box reports a `/run/docker/netns/<id>` entry, which the operator explains as `nsfs`. It is accepted here as explained, but D2.1's pass rule only says "any `memory_sweep` hit", which leaves reviewers to interpret it. **Recommendation:** have the collector classify `nsfs` (and other non-regular special files) separately from `unreadable`, or have the checklist pre-explain `/run/docker/netns/*`.
4. **D4.2's baseline is not in the reviewer's packet.** The brief gives the reviewer no earlier report, yet D4.2 compares against one. **Recommendation:** the operator's evidence (or the bundle) carries the last PASS `execstart_sha256`.
5. **Minor inconsistency in the operator's evidence.** Its header says "For checklist v1.9", but the review runs against v1.10 (explained at its end). **Recommendation:** correct the header for the record.
