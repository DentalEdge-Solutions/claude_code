## Not on the checklist

1. **Customer-id fingerprints are not a redaction.** The operator's evidence file gives a truncated SHA-1 of each client's Google Ads customer id. A customer id is 10 digits, so the whole space (10^10) can be hashed offline in minutes, and a sha12 of it is effectively the id itself. A sha12 of a refresh token is safe because tokens have high entropy; a sha12 of a customer id is not. **Recommendation:** treat customer-id fingerprints as customer ids. Keep them out of files that leave the box, or use a keyed HMAC with a box-local key. This report reproduces none of them.
2. **The operator's evidence file contains real client slugs and customer-id fingerprints, and it sits in the repository tree** (`infra/hermes-agent/security-reviews/`). F21's policy is that real slugs never leave the box in a doc or PR, and D9.1 accepts that review reports are public. **Recommendation:** replace the slugs with `<client>` and remove the customer-id fingerprints before this file is committed or pushed. If it is already committed to a public branch, decide whether history needs rewriting. It also carries the last four characters of the deleted Anthropic key: harmless now the key is deleted, but a habit to drop.
3. **A customer id in the assistant session (incident, 2026-09-29).** "In no file, commit or log on the box" does not cover the laptop: session transcripts are stored locally (and by the provider). **Recommendation:** record it as a finding with a D9.1 decision (see D9.1). Consider whether the local transcript should be deleted.
4. **The LLM steps read untrusted, client-controlled data, and the box now has a real API key and a Google credential.** Ad text, campaign names and similar fields reach the Opus draft step. D4.1 proves the *gateway* cannot see the Google credential, but no item proves the same for the containers `run-client-audit` starts (the collect and draft steps). The read credential's platform backstop (READ_ONLY) limits it to data exfiltration, which is still client data. **Recommendation:** add a checklist probe that the draft/analyst step's environment and mounts contain no Google Ads credential and that the collect step alone holds it. Consider egress restrictions for the analyst step. The $20 monthly limit on `hermes-box` bounds cost, not exfiltration.
5. **`memory_sweep.unreadable` needs a rule or a collector fix.** Docker creates `/run/docker/netns/*` handles on every running container, so this entry will recur at every review. **Recommendation:** have the collector check the filesystem type (skip `nsfs` and report it as `ns-handle`), or add an explicit operator-explanation route to v1.9. Until then, the operator should attach `sudo stat -f -c %T /run/docker/netns/<id>` (expected `nsfs`) and `findmnt` for that path.
6. **`/etc/sudoers.d/90-cloud-init-users`.** This stock file often grants `NOPASSWD: ALL` to the image's default user. No such login account exists today (D1.5), but if one is created later it gets passwordless root. Its contents are not in the bundle. **Recommendation:** the operator confirms which user it names and removes it if that user does not exist. A later checklist could hash `sudoers_d` contents.
7. **`/opt/hermes-agent/data/reports` is outside the bundle.** The operator states it is `10000:hermes 700`. It holds audit output, which is client-derived. **Recommendation:** add it (and `audit-logs`) to the D7.1 collector so both are measured, not stated.
8. **The retired ADMIN write token is still valid** (accepted risk, D3.2). It is noted here only because it is the largest residual: any copy that survives, for example in a transcript or an old backup outside the ones listed, would be a live ADMIN mutate credential. The operator's statement that no backup exists is the only control.
9. **Registry integrity rests on runbook discipline.** The 2026-09-29 incident (an empty `clients.json` installed by an improvised paste) failed closed, which is good. **Recommendation:** have the registration tooling refuse to install an empty or unparsable registry, so the protection lives in code as well as in PR #76's procedure.
